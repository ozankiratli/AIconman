## The groundwork

Built first, since every later part needs it and none of it waits on a decision of Z's.

- **`aiconman/`**, a Python package at the repository's root, run by Uvicorn as `uvicorn --factory aiconman.app:create_app`.
- **`aiconman/config.py` is the only reader of the configuration.** It reads `config.yml` from `config/` or the folder `AICONMAN_CONFIG_DIR` names, fills each secret left empty there from `.env`, and checks that every setting the backend needs is there and of its type, naming the setting when one is not. The scripts in `install/` had read `config.yml` with code of their own and filled the secrets by sourcing `.env` in bash; two readers of one file can come to disagree, so `install/common.sh` now runs `aiconman/config.py` as a script, which prints the settings as shell assignments, and its own `.env` fallback is gone. `.env` is now read by Python, one `KEY=value` per line, with quotes around a value removed and nothing else interpreted; a line that is not `KEY=value` is refused, naming its line. As before, a secret in the calling shell's environment is not read.
- **What the backend needs from the configuration**, the agent's reading of the template: the server's address and `public_url`; the database and the app role, not the owner; the storage folder; the sign-in settings; and the connections' key. Nextcloud's settings and `auth.state_secret` are needed only while Nextcloud sign-in is on. With both ways of signing in off, password sign-in is on, as the template says. Nextcloud's addresses are made from `instance_address`, and `redirect_uri` from `public_url`, unless set.
- **`aiconman/db.py`** connects as the app role and calls the schema's functions, the only thing that role may do. A function's refusal, SQLSTATE `AI001`, becomes `Refused` with its key.
- **`aiconman/app.py`** answers a refusal with its key as JSON, `{"error": "last_admin"}`, and an HTTP status: 401 for a session that cannot be used; 403 for a person not allowed, `not_admin`, `password_change_required`, `deactivated` and `sign_up_closed`; 404 for a key naming something that does not exist; 409 for one naming something taken; 400 otherwise. `GET /api/health` says whether the backend reaches its database and finds the schema seeded.
- **FastAPI's own documentation pages are off.** Fetched from a default FastAPI application in the agent's process, `/docs` loads from `cdn.jsdelivr.net` and `fastapi.tiangolo.com`, and `/redoc` also from `fonts.googleapis.com`; the interface loads nothing from outside the household's network (`the-interface.md`).

## How it is tested

- **The standard library's `unittest`**, so no test library is added; the tests are in `tests/backend/`.
- **No server is started and no port is touched.** The application runs inside the test's own process, reached through HTTPX's transport for an application. Starlette's test client, which FastAPI offers, warned on import that using HTTPX with it is deprecated, so it is not used.
- **`tests/backend/test_config.py`**, 18 tests on configurations in temporary folders, needs no database: secrets from `config.yml`, from `.env`, and which wins; `.env`'s quotes, comments and blank lines, and a line refused; the calling shell not read; a missing file, a file that is not YAML, a setting missing, a port and a switch of the wrong type; password sign-in on when both are off; Nextcloud's settings needed only when its sign-in is on, its addresses made and overridden; the templates, filled in, loading; and the script's shell assignments, read back by bash, a quote and a dollar sign intact.
- **`tests/backend/test_app.py`**, 6 tests against the scratch database as the app role, refusing to run without `AICONMAN_CONFIG_DIR` or with it naming `config/`: the health check; the documentation pages answering 404; refusals answered with their key and status; a function's rows; a refusal coming back as `Refused` with its key; and the app role refused a table. They pass with deprecation warnings raised as errors.
- **Two copies with a rule broken** each fail the test for it: refusals not recognized as such, and every refusal answered 400.
- **The scripts' tests pass through the new reader**: `tests/install/test_create_database.sh`, with its `.env` cases, `tests/install/test_build_schema.sh`, and `tests/db/run.sh`.

## Added later on 2026-10-12, against `1974f52`: password accounts

Z committed the groundwork as `1974f52`, *"FastAPI backend ground work"*, and answered the agent's three questions: *"1. Password accounts make sense. Build them. 2. Password hashing, definitely. 3. Agreed."* So password accounts are built now, ahead of the interface; Nextcloud sign-in, which was to be reused from Z's other project, comes after the interface works. Passwords are hashed with scrypt from Python's standard library. And the reads the connections and chat need are proposed in the reading log before those stages: R-018 to R-020.

**Built:** `aiconman/passwords.py`, `aiconman/sessions.py`, `aiconman/storage.py` and `aiconman/accounts.py`, the endpoints under `/api`: the options a sign-in page needs (`GET /api/auth/options`); signing up, in and out; one's own account, its sessions elsewhere, username, display name, theme and password, giving up the admin role, and deleting it (`/api/me`); and the admin's accounts and settings (`/api/admin`). Linking and unlinking Nextcloud wait for Nextcloud sign-in.

**What the agent decided, for Z to keep or change:**

- **scrypt's cost is N = 2^17, r = 8, p = 1**, with a 16-byte random salt and a 32-byte hash. On this machine one hash took 486 ms and 128 MiB; N = 2^16 took 226 ms and 64 MiB, and 2^15 113 ms and 32 MiB. The cost is written into each password's salt string, `scrypt$n=131072,r=8,p=1$<salt>`, so it can be changed for new passwords without breaking old ones. A password is hashed in a thread, so that the server goes on answering meanwhile.
- **A password is normalized to NFC before it is hashed**, so that the same characters typed on another device sign in.
- **The password rules, read from Z's** (*"16 char min 2 uppercase 2 lowercase 2 number 2 symbol minimum"*): at least 16 characters; at least two letters each that Unicode counts as uppercase and as lowercase; two digits; and two symbols, a symbol being any character that is not a letter, a digit or a space. A password over 1024 characters is refused as malformed. A weak one is refused with the rules it misses, by name, for the interface's checklist.
- **Signing in with a username that does not exist answers as a wrong password does**, without hashing anything, so its answer comes sooner. Usernames are not hidden: signing up says when one is taken.
- **The session cookie** holds 32 random bytes; only their SHA-256 reaches the database. It is hidden from the page's scripts, sent only to this site (`SameSite=Strict`), sent only over HTTPS when `auth.cookie_secure` is on, and kept as long as a session can last at most; the database decides when a session ends earlier. `SameSite=Strict` also keeps it off the request that brings a person back from another site, which matters when Nextcloud sign-in is built: its callback will need a cookie of its own.
- **A request that changes something is refused when its `Origin` header names another site than `server.public_url`**, as a second guard beside `SameSite=Strict`. A request without one passes. From the agent's knowledge, not from a read, browsers send `Origin` with every request from another site and with every request of their own site that is not a GET or a HEAD. A consequence for anyone setting AIconman up: `public_url` must be the address in the browser's bar, scheme, host and port, or every change is refused.
- **A deleted account's folder** is removed after the database has deleted the account. If removing it fails, the failure is logged and the answer says `"folder_removed": false`; the account is gone either way.
- **The admin creates accounts only while password sign-in is on**, since such an account signs in with its first password.
- **A malformed request** is answered 400, `{"error": "request_invalid", "fields": [...]}`, like every refusal, rather than FastAPI's own 422.

**How it was checked.** `tests/backend/test_accounts.py`, 22 tests, each against a schema rebuilt for it, through the application in the test's process, each person a client with their own cookie and the site's own `Origin`: the options; a weak password and the rules it misses; the first account the admin; the cookie's attributes; signing in, failing, and signing out; a password typed in another Unicode form; no cookie and an unknown one; a request from another site refused, one without `Origin` passing; a malformed request; password sign-in switched off; signing out elsewhere; changing one's username, display name, theme and password; deleting one's account and its folder; a member refused administration; an account the admin creates having to change its password first; a reset; closing and reopening sign-up; making and giving up the admin role; deactivating; and deleting an account and its folder. Most lower scrypt's cost to 2^10 to keep the run short; the salt string carries the cost, so the path is the same. One runs at the real cost and reads what the database stored: the salt string with the real cost, a 32-byte hash that the password reproduces, and no trace of the password. All 46 of the backend's tests pass, with deprecation warnings as errors. Three copies with a rule broken each fail the test for it: no NFC, no check of `Origin`, and a cookie sent with `SameSite=Lax`.

## Added later on 2026-10-12, against `1974f52`: Z's review of the password accounts

Z staged the password accounts without committing them, with two changes to the agent's decisions above:

- **Symbols, spaces and pasted passwords.** Z: *"Symbol is anything that is not alphanumeric. Numbers don't count as symbols. Space should not be allowed in the password also if there is whitespace left when the user copy their passwords etc, it should be automatically removed."* So whitespace at either end of a password is removed before it is checked or hashed, at every step that takes one: signing up, signing in, changing it, and the admin's creating and resetting. Whitespace left inside is refused, as the rule `spaces`. A symbol is any character that is not a letter or a digit; whitespace, refused anyway, is not counted as one, so that the interface's checklist does not tick symbols for a password it refuses for its spaces. Trimming and NFC are one function, `passwords.normalized`, which both the rules and the hashing use.
- **The refusal's name.** Z: *"Wrong credentials" would be the right error.* The refusal of a wrong password and of an unknown username, one and the same, is now `wrong_credentials`, renamed from `sign_in_failed` in the schema, the backend and their tests by an announced `sed`.

**Checked:** three more tests, 49 in all: a password signed up with whitespace around it signs in with it and without it; a space inside is refused as `spaces`; and a password with digits and no symbols misses only `symbols`. The schema's 256 checks pass with the renamed key. Two copies with a rule broken each fail the test for it: no trimming, and spaces allowed.
